# V6.3 — Timetable and Examination Analysis

## Timetable module delivered in the browser preview
- School day configuration: 5 or 6 days, periods per day, lesson duration, start time and break settings.
- Teacher register with weekly maximum teaching load.
- Education stage, grade and stream register.
- Weekly subject/learning-area requirements linked to a class and teacher.
- Room/facility allocation.
- Single and preferred double-period blocks.
- Automatic slot allocation with hard checks for teacher, class and room clashes and teacher weekly maximums.
- Unplaced lesson report rather than silently dropping requirements.
- Class, teacher, room and whole-school master timetable views.
- CSV export.

### Scheduler limitations
The browser preview uses a heuristic greedy scheduler with randomized tie-breaking. It does not yet solve a global constraint optimization problem, manage teacher availability calendars, fixed events, teacher qualifications, subject-spread preferences, substitutions, or atomic server-side publishing. A generated result is a draft and must be reviewed. Production generation must run in a trusted backend scheduling service with transaction-level conflict validation and immutable published versions.

## Examination analysis module delivered in the browser preview
- Manual result entry.
- Bulk CSV import.
- Raw score, maximum score and percentage validation.
- Subject mean, median, highest, lowest and standard deviation.
- Grade and stream performance comparisons.
- Learner merit list based on the mean of entered subject results.
- Performance-level distribution.
- Result register and CSV export.
- Selectable KJSEA 2025 reference bands or a clearly labelled illustrative internal band profile.

### Assessment limitations
The internal A–E bands are examples only and must be configured by each school. KJSEA bands are applied only when the user selects the KJSEA 2025 profile. Do not sum KJSEA subject points into a simple aggregate. Learner mean/ranking must be interpreted with caution where learners have different subjects or missing entries. Production analysis must define denominators, missing-result handling, subject weighting, tie rules, approved result snapshots and role permissions.

## Live database migration
Apply `database/004_v63_timetable_engine.sql` after migrations 001–003 in a dedicated development Supabase project. It adds timetable templates, periods, teacher availability, weekly requirements, versioned timetables and timetable entries with school-scoped foreign keys and RLS. The current HTML preview is local-browser data and does not yet persist to these new tables.

## Production acceptance tests still required
- No teacher, class or room overlap, including double/triple period blocks.
- No period outside configured school days/hours and no protected break use.
- Weekly allocated periods exactly match approved requirements or show every unplaced period.
- Teacher workload limits and availability respected.
- Published timetable version is immutable; changes create a new version.
- Exam marks are range-checked and moderation/approval/locking enforced.
- Analysis denominators, missing marks, weights, ties and band boundaries are transparent and tested.
- Role and tenant isolation tests across at least two schools.
