# V6.5.1 static review – 12 November 2026

## What was checked
- ZIP archive integrity.
- Migration ordering and the timetable requirement composite unique key.
- Browser configuration for service-role/secret key strings.
- Operations UI report snapshot write path (INSERT, not UPSERT).
- V6.5 hardening migration policy and trigger logic.

## Additional source corrections in this review copy
- Teacher mark access now explicitly requires active school membership as well as a leadership role or a linked, active staff profile with a qualified learning-area assignment.
- A mark cannot be moved out of an approved, locked or archived assessment by updating its assessment reference.

## Remaining blockers – do not deploy
1. Report snapshots have a unique constraint on (assessment_id, learner_id), so the promised versioned correction workflow is not yet implemented.
2. Timetable publication accepts both `draft` and `validated`; the intended validated-only gate is not enforced.
3. Timetable entries are not generated by a complete solver/editor in the UI.
4. Teacher access is learning-area scoped, not class/stream scoped; class-teacher assignment workflows are absent.
5. Operations UI still loads broad school-level records and assumes one active membership; do not expose it to teacher accounts.
6. Parent/learner portal access, full audit coverage, retention automation, backup restoration, accessibility and load tests remain outstanding.
7. No live PostgreSQL/Supabase execution or two-tenant runtime test was performed in this environment.

## Release decision
Development review copy only. Use a new disposable Supabase development project, apply migrations in documented order, and complete every test in `docs/V6.5_TEST_PLAN.md` before considering any pilot. Do not use the existing Junior School Learning Hub production Supabase project.
