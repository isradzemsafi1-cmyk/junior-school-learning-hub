# Digital School Centre V6.9 — Automatic Timetable Generator

## Included
- Browser-based weekly timetable configuration for 5–7 days and 2–16 periods/day.
- Teacher registry with weekly maximum teaching loads.
- Grade/stream teaching groups with home rooms and daily period limits recorded.
- Weekly learning-area requirements, assigned teacher, room, preferred double/triple block and optional fixed day.
- Most-constrained-first scheduling with block placement, then a single-period recovery pass.
- Hard clash checks for teacher, teaching group/class and room occupancy; weekly teacher-load validation.
- Unplaced period report rather than silently dropping unmet requirements.
- Whole-school, class, teacher and room views; CSV export; browser print / Save as PDF.
- Local browser draft persistence under `dsc_tt_v69`.

## Use
Open `app/timetable.html` or select Automatic timetable generator from the V6 application home page. Configure days and periods, add teachers and teaching groups, add weekly requirements, then generate. Review unplaced periods and validation results before exporting or printing. Use sample configuration only to explore; replace it with actual school data.

## Important operational limits
This is a functional local development scheduler, not a live multi-user timetable publishing service. It does not write generated schedules into Supabase, perform atomic database publication, or fetch staff/class/room data from the authenticated school tenant. The existing migration `004_v63_timetable_engine.sql` defines the persistence schema, but a trusted server-side scheduling/publishing RPC and end-to-end tenant/RLS tests are still required before production publication. The current generator uses a randomized tie-breaker, so repeated drafts can differ; always review and validate the final draft. Room and class clash rules are enforced by the local generator. The configured daily class maximum is retained as setup metadata but must be checked during future server-side hardening.

## Test coverage
Static JavaScript syntax check and archive integrity check are performed for this release. Manual acceptance testing with each school's actual teacher allocations, rooms, availability, double periods, fixed sessions, and workload limits is required before deployment.
