# V6.10 — JSLH Examination Analytics

## Included
- School-authenticated examination workspace using the V6 Supabase client configuration.
- School membership resolution and school-scoped reads/writes through the existing RLS-protected V6 tables.
- Examination creation, learning-area components and the existing assessment status RPC workflow.
- Individual result entry with numeric range validation and upsert by assessment/component/learner.
- CSV import with row validation before writes, admission-number and component-title matching, 100-row batches, and rejection report.
- Automatic school overview, learning-area means, median, highest, lowest, population standard deviation, grade/stream comparisons and configurable internal band distribution.
- Learner merit lists with competition ranking for ties and transparent missing-result warnings.
- Printable individual and batch report cards; immutable report-card snapshots for approved/locked assessments.
- CSV exports for detailed analysis and merit lists.

## Existing database objects used
This module uses the V6 schema already present in migrations 001–006:
- school_memberships, schools
- academic_years, academic_terms, school_grades, school_streams
- learning_areas, learners
- school_assessments, assessment_components, assessment_marks
- report_card_snapshots
- set_assessment_status(p_assessment_id, p_status) RPC

No database migration is required for this UI package. Do not run migrations against the existing production Junior School Learning Hub database.

## Calculation rules
- Percentage = raw_score / maximum_score × 100.
- Missing numeric scores are excluded from means, medians, standard deviations and ranking; they are never silently converted to zero.
- Subject/learning-area statistics use recorded numeric component rows.
- Learner ranking uses the unweighted mean of numeric component percentages actually recorded for that learner. Learners with different subject counts are not directly comparable; the UI discloses this.
- Equal means share a rank (competition ranking).
- The internal four-band profile is illustrative and browser-local, editable by the school. It is not represented as official KNEC/KJSEA grading.
- Descriptor, rubric, portfolio and competency evidence is displayed as qualitative evidence and not converted into a numeric percentage.

## Workflow
Draft → Open → Submitted → Moderation → Approved → Locked. The database RPC and triggers enforce transitions and prevent changes to finalised marks. Report snapshots are append-only; the UI does not overwrite historical snapshots.

## Release and safety gates
- Development branch and Deploy Preview only; do not merge into main or deploy to the production domain.
- Test using a dedicated V6 development Supabase project and fictional learner records.
- Verify RLS and role access for at least two independent schools and teacher subject assignments.
- Validate CSV imports, grading configuration, workflow transitions, ranking denominators, report printing and snapshot immutability before production consideration.
- The current module does not send SMS, perform official KNEC certification, or replace professional teacher judgement.


## V6.11 enhancement layer (development preview)
- Adds a class-roster marks-entry table for one assessment component, with prefilled existing marks, grade/stream filters, score-range validation, batch upsert, and read-only display unless the assessment status is OPEN.
- Adds a learner progress view using recorded assessment marks across the learner's available examination history, grouped by learning area.
- Adds an intervention screening prompt for learning-area means below 50%; this is explicitly an illustrative school support threshold, not an official KNEC grade or an automated judgement.
- Adds a qualitative CBE evidence register showing achievement descriptors, teacher comments and evidence references already stored against marks.
- Implemented as a separate enhancement script loaded by the existing page. No production database writes, migrations, schema changes, or new tables are included.

## Additional verification gates
- The existing production RLS policy for the learners table currently allows learner reads to school leadership/administrative roles, but does not include teacher or class_teacher. Therefore roster entry for those roles is not yet confirmed and must not be advertised as available to them until assignment-scoped learner access is designed and tested.
- The connected school currently has no academic-term rows returned for its workspace. Configure academic years and terms in Academic Operations before relying on term-based examination records.
- The enhancement layer must be tested in a deploy preview with fictional records for numeric and descriptor components, multiple streams, locked assessments, missing scores, historical exams and cross-school isolation.
- Learner progress currently orders examinations by record creation time; this should be validated against the school's intended academic-year/term sequence before formal reporting.
- Do not merge this development PR into production until the above checks and a browser smoke test pass.

 
## V6.12 — CBE READY expansion (development branch)
The V6.12 work is additive. It retains the V6.10 examination register, marks entry, CSV import, analysis, merit list, printable reports and immutable snapshots.

### New application capabilities
- Class-roster marks entry and learner progress are provided by the V6.11 enhancement layer.
- School-managed curriculum map for learning areas, strands, sub-strands, competency references and learning outcomes.
- Component-to-strand mappings with configurable weights for strand/sub-strand analysis.
- Component-level achievement descriptor scales stored with the assessment component. Codes and labels are school-authored; numeric marks are not silently translated into official CBE/KNEC levels.
- Learner support/intervention register with concern evidence, planned support, review date, status and outcome.
- School-specific screening threshold and percentage bands are persisted in `school_cbe_settings`; they create school-configured indicators only and are not official KNEC grades.
- Assignment management for staff users by grade, optional stream and optional learning area; teacher and class-teacher reads/writes are scoped to active assignments, and full report snapshots are restricted to class-wide assignments or school leaders.
- Parent/guardian portal reads only linked learner profiles and published approved/locked report-card snapshots.
- Guardian communication outbox schema is included for a future SMS/email provider integration. It does not send messages until a provider and secured server-side delivery function are configured.

### Migration
Apply `digital-school-centre/v6/database/migrations/007_cbe_ready_v6_12.sql` to a dedicated development Supabase project first. It creates the curriculum, assignment, intervention, settings and guardian outbox tables and adds RLS policies. It also replaces school-wide teacher marks access with assignment-scoped policies and adds guardian access limited to linked learners and finalised results.
Do not apply this migration to the production project until the development preview, SQL policies, two-school isolation tests, teacher assignment tests and guardian tests pass and a production backup/change window is approved.

### Required setup and release gates
- Link each staff profile to its authenticated account (`staff_profiles.auth_user_id`) before creating assignments.
- Configure each school's academic years and terms; progress history sorts by academic-year dates and term sequence when present, with assessment date/name fallback.
- Link each guardian profile to a verified auth account (`guardians.auth_user_id`) and ensure `learner_guardians.can_receive_academic_updates` is enabled only with appropriate consent.
- Publish report-card snapshots only after the existing approval/lock workflow.
- Configure and test an SMS/email provider in a server-side function before enabling message delivery. Never place provider secrets in browser JavaScript.
- Run Supabase security and performance advisors after applying the migration; review all findings before production release.

### Known limitations
- This is not a complete official KNEC integration or automated diagnosis tool. School-entered descriptors and evidence remain subject to teacher judgement and school moderation.
- SMS/email delivery is not active; V6.12 provides a secure outbox foundation only.
- Parent access requires school-side guardian-account linking and a published report snapshot.
- The migration has been authored but has not been applied to the production database. No production database writes or live website changes are part of this development branch.
