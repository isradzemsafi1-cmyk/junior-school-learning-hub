# Digital School Centre V6.5 – Development hardening upgrade

## Purpose
This package is a development upgrade to the supplied V6.4 source. It preserves the existing V6 application structure and adds a reviewed migration sequence plus an explicit security boundary. It is **not** a production release.

## What changed
- `database/004_v63_timetable_engine.sql`: adds the missing `(id, school_id)` unique key on `timetable_requirements` before `timetable_entries` references it; safely replaces the timetable policies when this migration is rerun.
- `database/006_v65_security_and_workflow_hardening.sql`: adds learning-area-scoped teacher access to marks, checks assessment/component/learner consistency, protects finalised marks, enforces assessment status transitions through the RPC, makes report snapshots append-only, and prevents direct browser updates to timetable versions.
- `app/operations.html`: report snapshots now use INSERT rather than UPSERT, consistent with append-only report history.
- `docs/V6.5_TEST_PLAN.md`: staged test plan and explicit deployment gates.

## Correct migration order
For a **brand-new, separate V6 development Supabase project only**:
1. `database/001_v6_foundation.sql`
2. `database/002_v61_tenant_integrity.sql`
3. `database/003_v62_auth_onboarding_rls.sql`
4. `database/004_v63_timetable_engine.sql` (the corrected copy in this package)
5. `database/005_v64_live_assessment_and_publishing.sql`
6. `database/006_v65_security_and_workflow_hardening.sql`

Do not apply this sequence to the existing Junior School Learning Hub/V5 Supabase project. Do not run only migration 006 on an unknown or partially migrated database. Take a database backup before any migration and inspect the migration history first.

## Important operational limitations
- The UI is an administrator-oriented preview. It is not yet safe to expose as a teacher portal: it assumes one active school membership and loads broad school-level lists.
- Teacher marks access in the database is restricted to a staff profile linked by `auth_user_id` and a qualified `teacher_learning_areas` assignment. Class-teacher-specific assignment access is not implemented; class teachers do not receive broad teacher access from the new marks policy.
- No automatic timetable solver, drag-and-drop timetable editor, or complete timetable-entry generation service is included. A draft timetable version is not a timetable.
- Report snapshots are append-only in this upgrade. A formal correction/amendment and versioning workflow is still required.
- Parent/learner portal permissions, finance/M-Pesa, retention automation, complete audit coverage, backup restoration and accessibility/load testing remain future work.

## Configuration and secrets
`app/supabase-config.js` must contain only the V6 project's URL and public anon/publishable key. Never place a Supabase service-role key in browser code, repository files or Netlify public environment variables. Keep this V6 database separate from the currently working Junior School Learning Hub database and payment integration.

## Deployment rule
Use a separate GitHub repository and separate Netlify site/preview. Do not replace the existing live site, DNS, Netlify project, Supabase project, or payment functions. Do not enter real learner data until all test gates pass and a qualified reviewer has approved the security model.


## V6.5.1 static review amendments
- Teacher mark access explicitly checks active school membership.
- Mark rows cannot be moved out of a finalised assessment by changing their assessment reference.
- Timetable publication now requires `validated` status rather than accepting a draft.
- See `docs/V6.5.1_STATIC_REVIEW.md` for remaining release blockers. These source-level changes have not been executed against PostgreSQL.
