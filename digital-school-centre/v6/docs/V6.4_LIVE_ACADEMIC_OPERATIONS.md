# Digital School Centre V6.4 — Live Academic Operations

## What is added
- Assessment register with diagnostic, formative, summative, practical, project, portfolio and KJSEA types.
- Components support numeric marks, descriptors, rubrics, portfolios and competency evidence. This avoids forcing all CBE learning evidence into percentages.
- Learner-linked marks with raw score/max validation, achievement codes, comments and evidence references.
- Assessment lifecycle: draft → open → submitted → moderation → approved → locked. Locked marks reject direct mutation.
- Report-card snapshot storage for reproducible issued reports.
- Server-side timetable publication RPC that checks teacher, class/stream and room clashes again before publishing.
- Version archiving when a replacement timetable is published.

## Apply migrations in order
In a NEW Supabase development project, apply:
1. `001_v6_foundation.sql`
2. `002_v61_tenant_integrity.sql`
3. `003_v62_auth_onboarding_rls.sql`
4. `004_v63_timetable_engine.sql`
5. `005_v64_live_assessment_and_publishing.sql`

Do not apply this to the V5 production database. Use Supabase SQL Editor and review the migration with a database/security engineer before production.

## Existing V6.2 browser configuration
Edit `app/supabase-config.js` with the V6 development project's Project URL and public anon/publishable key only. Never put a `service_role` or secret key in browser code.

## Current scope and honest limitations
This release supplies the live database model, row-level security policies, controlled assessment lifecycle RPC and server-side timetable publication gate. The V6.3 academic operations preview remains a local demonstration and is not silently represented as live. The full live UI wiring for timetable generation, teacher qualification/availability, marks capture, moderation screens and PDF report cards is a subsequent integration task. The database does not itself constitute official KNEC/NEMIS/TSC integration.

Before real learner data:
- test tenant isolation with two separate school accounts;
- test teacher/administrator/leadership role boundaries;
- test the timetable publication RPC against deliberate clashes;
- test locked assessment mutation rejection;
- add school-specific assessment profiles and descriptor rubrics;
- review ODPC child-data privacy, retention, access logging and incident response.

## Important CBE/KJSEA treatment
Numeric marks, achievement descriptors, rubric evidence and portfolio evidence remain distinct. Do not convert every learning area to a percentage by default. KJSEA official reporting must use the applicable KNEC rules for the relevant examination year; internal school bands are configurable and must not be labelled as official KJSEA grades.
