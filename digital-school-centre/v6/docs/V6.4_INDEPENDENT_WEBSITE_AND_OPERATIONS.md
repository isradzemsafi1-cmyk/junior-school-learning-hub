# V6.4 Independent Website and Operations UI

## Recommended deployment model
Deploy this V6 package as a separate Netlify site (or other independent host), using this repository/package and its own V6 Supabase project. Keep the Junior School Learning Hub V5 site and database unchanged. Link the two sites with ordinary navigation links if desired. A subdomain such as `school.juniorschoollearninghub.co.ke` is a suitable V6 address if DNS is available.

## Deploy
1. Create a new GitHub repository for Digital School Centre V6; do not reuse or overwrite the V5 repository.
2. Upload the contents of this package to the new repository.
3. Create a new Netlify site from that repository. `netlify.toml` publishes the `app` directory.
4. Create a separate Supabase project for V6.
5. Apply database migrations `001` through `005` in order.
6. Set `app/supabase-config.js` to the V6 Project URL and public anon/publishable key only.
7. Configure Supabase Auth email confirmation and redirect URLs for the deployed V6 hostname.
8. Test with two school accounts and fictional learners before any real data.

## Operations UI delivered
`app/operations.html` is wired to Supabase for assessment creation, component creation, marks upsert, assessment lifecycle RPC, timetable template creation, weekly teaching requirement creation, timetable version creation, publication RPC and report snapshot creation/printing. It requires the V6 migrations and signed-in school membership.

## Remaining before production
The timetable version can be created and published only after entries exist; the automatic scheduling optimiser and entry-generation service are not included in this UI. Teacher qualification/availability checks, schedule editor, audit views, PDF report-card layout, guardian/learner access, payment/subscription and full privacy controls remain subsequent production work. Current report printing is a basic browser print view, not a designed PDF.
